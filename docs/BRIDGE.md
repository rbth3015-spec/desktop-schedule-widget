# Claude 연동 시트

> claude.ai 의 Claude 가 **구글 시트 한 장**으로 이 위젯의 일정을 읽고, 할 일 · 일정을 넣는다.
> 휴대폰 동기화가 쓰는 구글 드라이브의 숨김 앱 폴더는 같은 클라우드 프로젝트의 앱(위젯 · 폰)만 들어갈 수 있어 Claude 는 못 본다.
> 그래서 위젯이 사용자 드라이브에 시트를 하나 만들고 그 위로 주고받는다.
> 폰 앱은 이 시트를 모른다 — 위젯이 받은 것은 평소 휴대폰 동기화로 폰에 간다.

## 한눈에 보기

```
 위젯 ──통째로 덮어쓴다──▶ 일정 · 할 일 · 기록 탭 ──읽는다──▶ Claude
 위젯 ◀──5분마다 읽는다── Claude가 넣을 것 탭 ◀──줄을 더한다── Claude
      └──── 그 줄의 상태 · 처리시각 · 결과를 채운다 ────┘
```

## 켜기

1. 위젯 **설정 › 보관 › Claude 연동 시트 › `켬`**.
2. 기본 브라우저에 구글 로그인 화면이 뜬다 — 허용한다. 휴대폰 동기화를 구글로 쓰고 있으면 **같은 계정**이어야 한다.
3. **내 드라이브 맨 위**에 스프레드시트 `일정관리 비서 · Claude 연동` 이 생기고 첫 내보내기까지 끝난다.
4. 바로 아래 **시트 링크 › `복사`** 로 주소를 복사해 Claude 에게 준다(구글 드라이브가 연결된 claude.ai 대화에). `열기` 는 브라우저로 연다.

설정 줄에 `마지막 연동 3분 전` 이 보이면 연결된 것이다. 인터넷이 끊긴 동안은 `마지막 연동 40분 전 · 오류 8건` 처럼
실패한 횟수가 붙고(마우스를 올리면 이유), 다음 주기에 저절로 다시 한다.
로그인이 풀렸거나 · 시트를 지웠거나 · 시트 API 가 꺼져 있으면 횟수 대신 **그 이유와 할 일**이 그 자리에 뜬다.
이미 켜져 있을 때 `켬` 을 다시 누르면 지금 한 번 맞춘다(로그인이 풀렸으면 로그인부터).

## 권한

- 휴대폰 동기화의 `drive.appdata` 에 **`drive.file` 하나만 더한다** — 이 앱이 만든 파일(이 시트)만 다루고,
  드라이브의 다른 파일은 보지 못한다. ([SYNC.md](SYNC.md) 의 '권한은 drive.appdata 하나' 는 이 시트를 켜지 않았을 때의 이야기다.)
- 권한이 늘면 구글이 다시 묻기 때문에 **켤 때 로그인을 한 번 더 한다.** 앞서 허락한 권한은 새 토큰에 그대로 실린다
  (`include_granted_scopes`) — 휴대폰 동기화는 끊기지 않는다. 구글 화면에서 드라이브 파일 권한 체크를 풀면 켜지지 않는다.
- 휴대폰 동기화가 구글로 연결돼 있으면 같은 계정이어야 한다. 다른 계정으로 로그인하면 받지 않고, 있던 로그인을 그대로 둔다
  (계정이 바뀌면 동기화가 다른 드라이브를 보게 된다). 반대로 시트가 켜져 있는 동안 동기화를 다시 연결할 때도 같은 계정이어야 한다.
- 시트는 비공개로 만들어진다. Claude 는 사용자 계정의 구글 드라이브 연결로 연다 — 링크 공유 설정을 바꿀 필요가 없다.
- 위젯의 클라우드 프로젝트에 **Google Sheets API** 가 켜져 있어야 한다(드라이브 API 는 동기화 때 켜 두었다) — 아래 '프로젝트 주인이 할 일'.
  꺼져 있으면 `켬` 은 켜진 채로 두고 설정 줄에 `구글 시트 API 가 꺼져 있습니다 — 클라우드 프로젝트 <번호> 주인이 켜면 5분 안에 이어집니다` 가 뜬다.
  주인이 켜면 다음 5분 주기에 위젯이 저절로 시트를 만든다 — `켬` 을 다시 누를 필요가 없다(1.9.1).

## 클라우드 프로젝트 주인이 할 일

위젯 · 폰 앱의 구글 연결(OAuth 클라이언트)은 클라우드 프로젝트 하나에 들어 있다. 프로젝트 설정은 **그 프로젝트의 주인만** 바꿀 수 있다 —
다른 계정으로 콘솔을 열면 '프로젝트를 고르라' 는 화면만 나온다.

1. **Google Sheets API 사용** — API 및 서비스 › 라이브러리 › Google Sheets API › `사용`.
   이 프로젝트면 `https://console.developers.google.com/apis/api/sheets.googleapis.com/overview?project=<번호>` 가 바로 그 화면이다.
2. **앱 게시** (권장) — Google 인증 플랫폼 › 대상 › `앱 게시`. '테스트 중' 이면 테스트 사용자만 로그인할 수 있고
   **로그인이 7일마다 끊긴다** — 휴대폰 동기화도 같이 멈춘다(2026-10-08 ~ 10-25 에 실제로 그랬다).
   이 앱이 쓰는 권한(`drive.appdata` · `drive.file`)은 민감하지 않은 권한이라 구글 심사 없이 게시된다.

## 시트 모양

탭 넷. 모든 탭의 **1행은 한 줄 안내**(내보낸 시각 · 담은 범위, 받은편지함은 쓰는 법), **2행은 머리글**, 3행부터 값이다.
위젯이 쓰는 값은 전부 글자다(시트가 날짜 · 숫자로 바꾸지 않는다).

### 일정 — 위젯 → 시트

| 칸 | 값 |
|---|---|
| id | 위젯의 일정 id. 반복 일정의 회차들 · 여러 날 일정의 날마다는 id 가 같다 |
| 날짜 | `YYYY-MM-DD` |
| 시작 · 끝 | `HH:MM`. 종일이면 빈칸. 여러 날 일정은 첫날에 시작, 마지막 날에 끝 |
| 제목 | |
| 태그 | `#공부 #자격증` |
| 완료 | `예` · `아니오` — 반복 일정은 회차마다 |
| 반복 여부 | `매일` · `격일` · `평일` · `주말` · `매주 월·수` · `매월` · `매년`. 반복이 아니면 빈칸 |

- 범위는 **오늘 기준 지난 14일 ~ 앞으로 90일**, 하루씩. 달력이 그날 그리는 그대로다 — 반복 일정은 회차마다, 여러 날 일정은 날마다 한 줄.
- 루틴(달력에 그리지 않는 습관)과 날짜 없는 '언젠가' 는 싣지 않는다. 검색어 · 태그 필터는 보지 않는다.

### 할 일 — 위젯 → 시트

| 칸 | 값 |
|---|---|
| id | 할 일 id |
| 내용 | |
| 날짜 | 그 할 일이 보이기 시작하는 날 `YYYY-MM-DD`. 못 끝낸 것은 다음 날로 이어진다 |
| 완료 | `예` · `아니오` |
| 묶인 일정 시각 | '시간 잡기' 로 만든 일정 — `2026-10-24 15:00–16:00`. 없으면 빈칸 |

안 끝낸 할 일 전부와 최근 14일 안에 끝낸 것. 날짜순.

### 기록 — 위젯 → 시트

최근 30일(오늘 포함)의 한 줄 기록. `날짜` · `내용`, 날짜순.

### Claude가 넣을 것 — 시트 → 위젯

| 칸 | 누가 | 값 |
|---|---|---|
| 요청ID | Claude | 줄마다 새것. **같은 요청ID 는 두 번 만들지 않는다** |
| 종류 | Claude | `할일` · `일정` (`할 일` 도 된다) |
| 내용/제목 | Claude | 200자까지 |
| 날짜 | Claude | `YYYY-MM-DD`. 비우면 오늘 |
| 시작 · 끝 | Claude | `HH:MM`, 일정만. 할 일에 적으면 쓰지 않는다 |
| 메모 | Claude | 일정은 메모 칸으로, 할 일은 내용 뒤에 ` — 메모` 로 붙는다 |
| 상태 | 위젯 | **비어 있거나 `대기` 인 줄만 처리한다** → `반영됨` · `오류` |
| 처리시각 | 위젯 | `YYYY-MM-DD HH:MM` |
| 결과 | 위젯 | `반영됨` 이면 만든 할 일 · 일정의 id, `오류` 면 이유 |

- 들어온 할 일 · 일정에는 **`#공부`** 가 붙는다 — 할 일은 글 끝에(할 일에는 태그 칸이 없다), 일정은 태그로.
  일정의 색은 `#공부` 태그에 가장 많이 쓴 색.
- **추가만 한다.** 있던 일정 · 할 일을 고치거나 지우지 않는다.
- 위젯의 받은함과 같은 길(store 의 일정 추가 · 할 일 추가)로 들어가므로 화면 · 휴대폰 동기화가 평소대로 돈다.
  들어오면 `Claude 연동 시트에서 일정 1건 · 할 일 3개를 받았습니다` 토스트가 뜬다(하루치 할 일만 왔으면 되돌리기 단추도).
- 처리한 요청ID 는 사용자 데이터 폴더의 `claude-bridge-done.json` 에 남는다(시트마다, 최근 3000개).
  누가 상태 칸을 지워 다시 비워도 만들지 않고 처음 결과를 되적는다. 같은 요청ID 에 다른 내용이 오면 `오류`.
- 칸은 머리글 이름으로 찾는다 — 칸 순서를 바꾸거나 칸을 더해도 된다. 머리글 줄을 지우면 처리하지 않는다(설정 줄에 뜬다).
- 처리하는 동안 누가 위쪽 줄을 지우거나 끼워 넣었으면, 쓰기 전에 다시 읽어 같은 내용의 줄을 찾아 쓴다.

오류 이유 예 — `종류는 '할일' 또는 '일정'입니다 ('할일ㅇ')` · `날짜는 YYYY-MM-DD 로 적습니다 ('10/25')` ·
`시작은 HH:MM 으로 적습니다 ('9시')` · `끝 시각이 시작보다 이르거나 같습니다` · `요청ID가 비어 있습니다` ·
`같은 요청ID가 5행에 있습니다` · `이미 다른 내용으로 처리한 요청ID입니다 — 새 요청ID를 쓰세요`.

### Claude 에게 줄 말 (예)

> 이 시트가 내 일정관리 비서야: <시트 링크>
> '일정' · '할 일' · '기록' 탭은 읽기만 하고, 넣을 것은 'Claude가 넣을 것' 탭 맨 아래에 한 줄씩 더해 줘.
> 요청ID 는 줄마다 새로(예: 20261024-1), 상태 · 처리시각 · 결과는 비워 둬. 5분쯤 뒤에 결과 칸을 보면 들어갔는지 알 수 있어.

## 주기

- **켜질 때**(위젯이 뜨거나 `켬` 을 누를 때) 한 번, 그리고 **5분마다** — 내보내기 + 받은편지함.
- 위젯에서 일정 · 할 일 · 기록이 바뀌면 **30초 모아서** 내보낸다. 받은편지함은 5분 주기에만 읽는다.
- 인터넷이 끊기면 조용히 다음 주기에 다시 한다. 트레이 · 화면에는 띄우지 않고 설정 줄에만 보인다.
- 내보내기는 세 탭을 `batchUpdate` 한 번으로 통째로 갈아 쓴다 — 읽는 쪽이 반쯤 쓴 표를 보지 않는다.
  사람이 내보내기 탭을 고치려 하면 시트가 한 번 묻는다(다음 내보내기에 덮인다). 탭을 지우면 다음 주기에 다시 만든다.

## 끄기

**설정 › 보관 › Claude 연동 시트 › `끔`.** 위젯이 시트를 더는 읽고 쓰지 않는다.

- 시트는 드라이브에 남는다(지우려면 드라이브에서). 다시 켜면 같은 시트를 이어 쓴다 — Claude 에게 준 링크도 그대로다.
- 시트를 지웠거나 휴지통에 넣었으면 설정 줄에 `시트를 찾을 수 없습니다` 가 뜬다. 끄고 다시 켜면 새로 만든다(링크가 바뀐다).
- 휴대폰 동기화가 구글을 쓰지 않으면 끌 때 이 PC 의 구글 로그인도 지운다. 동기화가 쓰고 있으면 남긴다.
- 구글 쪽 권한까지 거두려면 구글 계정 › 보안 › 타사 앱 — 같은 클라우드 프로젝트라 **휴대폰 동기화 권한도 함께 사라진다.**

## 코드

| 파일 | 하는 일 |
|---|---|
| `src/main/claude-bridge.js` | 시트 만들기 · 내보내기 · 받은편지함 읽기 · 상태 쓰기(시트 REST), 주기 / 받은편지함 해석 · 행 변환(순수 함수) |
| `src/renderer/claude-bridge.js` | store 를 읽어 내보낼 재료로(반복 회차는 렌더러만 펼친다), 받은 요청을 store 액션(`addTasks` · `addTodos`)으로 |
| `src/main/google-auth.js` | 로그인에 권한 더하기(`drive.file`) · 같은 계정인지 보기 · 받은 권한 기록 |
| `tests/claude-bridge*.test.mjs` | `npm test` — 해석 · 행 변환, 가짜 구글 시트로 켜기 → 내보내기 → 받은편지함, store 와 맞물리는지 |

사용자 데이터 폴더에 `claude-bridge.json`(켬/끔 · 시트 ID · 주소 · 탭 ID · 만든 계정)과
`claude-bridge-done.json`(처리한 요청ID)이 생긴다. 휴대폰 동기화의 파일 계약([SYNC.md](SYNC.md))과
합치기 규칙(`src/renderer/sync/crdt.js`)은 건드리지 않는다.
