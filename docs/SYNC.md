# 휴대폰과 동기화

> PC 위젯과 안드로이드 앱이 **같은 폴더 하나**를 바라보게 하면, 어느 쪽에서 넣고 고치고 끝내고 지워도
> 다른 쪽에 반영된다. 둘 다 따로 고쳐 두었다가 나중에 만나도 합쳐진다.
> 서버 · 계정 · 포트가 없다 — 폴더를 기기 사이로 옮기는 일은 OneDrive 같은 도구에 맡긴다.

## 한눈에 보기

```
 PC 위젯 ──쓴다──▶ 동기화 폴더/sync-pc-1a2b3c4d5e.json      ◀──읽는다── 폰 앱
 PC 위젯 ◀──읽는다── 동기화 폴더/sync-android-9f8e7d6c5b.json ◀──쓴다── 폰 앱
                         ▲
                 OneDrive · Syncthing 등이
                 이 폴더를 기기 사이로 옮긴다
```

- 기기마다 **자기 파일 한 장**만 쓴다. 쓰는 사람이 하나라 클라우드의 "충돌 사본"이 생기지 않는다.
- 파일 한 장에 그 기기가 아는 **전체 상태**가 들어 있다. 어떤 기기가 오래 꺼져 있어도 다른 기기의 파일을 거쳐 전해진다.
- 동기화되는 것: 일정 · 루틴 · 목표 · 언젠가, 할 일, 한 줄 기록, 돌아보기.
  동기화하지 않는 것: 설정 · 퀵 런처 · 알림 기록(기기마다 다른 값).

## 켜기

1. 위젯 **설정 › 보관 › 휴대폰 동기화 › 폴더 고르기** — OneDrive 안에 새 폴더를 하나 만들어 고른다(예: `OneDrive\일정동기화`).
2. 폰에서 그 폴더가 폰 저장소로 내려오게 한다.
   - OneDrive 를 쓰면: *Autosync for OneDrive* 나 *FolderSync* 같은 앱으로 그 폴더를 폰의 폴더 하나와 **양방향** 동기화.
   - 클라우드 없이: PC 와 폰에 Syncthing 을 깔고 그 폴더를 공유.
3. 폰 앱 **설정 › 동기화 폴더 고르기** 에서 2의 폴더를 고른다.

설정 줄에 `일정동기화 · 다른 기기 1대 · 3분 전` 처럼 보이면 연결된 것이다.
다른 기기에서 바뀐 것이 들어오면 위젯 아래에 `다른 기기에서 2건을 받았습니다` 가 뜬다.

> 받은 변경이 들어오면 **되돌리기 이력은 비워진다.** 되돌리기는 화면을 통째로 예전으로 돌리는 방식이라,
> 남겨 두면 Ctrl+Z 한 번에 폰에서 고친 것까지 되돌아가고 그 되돌림이 다시 폰으로 퍼진다.

## 합치는 규칙

- 일정 하나의 **필드마다** 따로 합친다. 폰에서 완료하고 PC 에서 제목을 고쳤으면 둘 다 남는다.
- 같은 필드를 양쪽이 고쳤으면 **나중에 고친 것**이 남는다. "나중"은 두 기기의 시계가 어긋나도
  "상대 변경을 본 뒤에 고친 것이 나중"이 되도록 센다(하이브리드 논리 시계).
- 반복 일정의 회차 완료(`doneDates`)·건너뛰기(`exceptions`)는 **회차마다** 합친다 —
  월요일 회차는 폰에서, 화요일 회차는 PC 에서 체크해도 둘 다 남는다.
- **지운 것은 지운 것으로 남는다.** 한쪽에서 지우는 동안 다른 쪽이 그 일정을 고쳤어도 되살아나지 않는다
  (지운 일정이 되살아나는 쪽이 더 나쁘다). 지운 쪽에서 되돌리기를 하면 다시 살아난다.

## 파일 모양 (버전 1)

```json
{
  "schema": "schedule-sync",
  "version": 1,
  "device": { "id": "pc-1a2b3c4d5e", "name": "DESKTOP-ABC", "app": "widget/1.7.0" },
  "savedAt": 1791234567890,
  "clock": "1791234567890:0003:pc-1a2b3c4d5e",
  "records": {
    "task:t_abc": {
      "title":                { "v": "치과", "t": "1791234567000:0000:pc-1a2b3c4d5e" },
      "doneDates@2026-10-06": { "v": true,   "t": "…" },
      "_del":                 { "v": false,  "t": "…" }
    },
    "todo:t_def":         { "text": { "v": "견적서 검토", "t": "…" } },
    "journal:2026-10-06": { "text": { "v": "좋은 하루", "t": "…" } },
    "retro:w:2026-10-04": { "text": { "v": "…", "t": "…" } }
  }
}
```

| 자리 | 뜻 |
|---|---|
| 파일 이름 | `sync-<기기ID>.json`. 기기ID 는 소문자 · 숫자 · `-` 3~64자 |
| 레코드 키 | `task:<id>` · `todo:<id>` · `journal:<YYYY-MM-DD>` · `retro:<w:YYYY-MM-DD \| m:YYYY-MM>` |
| 레지스터 | 필드 하나 = `{ "v": 값, "t": 스탬프 }` |
| 스탬프 | `<밀리초 13자리>:<카운터 4자리>:<기기ID>` — 문자열 비교가 곧 시간 비교 |
| 집합 원소 | `doneDates@<날짜>` · `exceptions@<날짜>` → `true` / `false` |
| 삭제 | `_del: true`. 없거나 `false` 면 살아 있다 |
| 한 줄 기록 · 돌아보기 | `text` 하나. 빈 문자열이면 없음 |
| 모르는 필드 | 건드리지 않고 그대로 실어 나른다(다음 버전이 더한 필드가 사라지지 않게) |

합치기: 레지스터마다 내 쪽에 없거나 상대 스탬프가 크면 상대 값을 가진다. 순서 · 중복과 상관없이 모든 기기가 같은 결과에 닿는다.

## 코드

| 파일 | 하는 일 |
|---|---|
| `src/renderer/sync/crdt.js` | 규칙 — 시계, 합치기, 화면 상태와의 diff, 펼치기, 스냅샷 검사(순수 함수) |
| `src/renderer/sync/sync.js` | store 구독 → diff → 발행 / 받은 파일 → 합치기 → `store.replaceSynced` |
| `src/main/sync.js` | 폴더 설정 · 감시(fs.watch + 20초 훑기) · 남의 파일 읽기 · 내 파일 원자적 쓰기 |
| `tests/sync-*.test.mjs` | `npm test` |

- 위젯은 store 의 액션을 하나도 고치지 않는다. 저장되는 데이터를 레플리카와 **필드 단위로 비교**해 달라진 필드에만 스탬프를 찍는다.
- 위젯 정규화가 받지 않은 레코드(예: 날짜 없는 할 일)는 화면에 없다. 그것을 "지운 것"으로 오해해 퍼뜨리지 않도록,
  지난번 화면에 있던 키(`known`)와 비교해서만 삭제를 찾는다.
- 사용자 데이터 폴더에 `sync.json`(폴더 · 기기ID · 이름)과 `sync-state.json`(내 레플리카 + `known`)이 생긴다.
- 안드로이드 앱 구현: 같은 규칙의 Kotlin 판(별도 저장소). 두 구현은 이 문서의 모양을 계약으로 삼고, 같은 시험 벡터로 결과를 맞춘다.
